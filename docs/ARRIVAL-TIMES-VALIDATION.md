# Arrival-time evidence and restart persistence

This unpublished development candidate follows the local Since display change and leaves the immutable beta 17 HACS release unchanged.

Use the exact explicitly selected usable map source. Registry-confirmed human Life360 trackers supply `at_loc_since`, independently from `last_seen`; HomeCircle-managed Life360 parsing now retains the server’s `since` value as well. Require timezone-aware, non-future evidence no later than the source report. The installed pet integration assigns its report time to `at_loc_since`, so it is explicitly excluded. No provider inference from entity names is used, and no additional cloud or location request is sent to obtain arrival evidence.

For other trackers, keep one current named-place checkpoint per configured member in the existing local HA activity store. Save the configured zone identifier, known observed arrival time and gap flag, without coordinates, addresses or routes. Genuine observed transitions replace the checkpoint; freshness updates do not reset it. Initial occupancy is unknown and old HA state timestamps are never migrated. Checkpoints remain independent of the seven-day/100-event timeline cap, reset with saved configuration changes, and disappear on integration removal.

On startup or unavailable gaps, preserve a matching place’s saved time and disclose unconfirmed continuity. A different place first seen after a gap has unknown arrival time. An observed departure followed by a new arrival establishes a new time. A restored away baseline permits the next observed arrival. Failed storage loading is not overwritten; persistence failure remains visible in the tooltip.

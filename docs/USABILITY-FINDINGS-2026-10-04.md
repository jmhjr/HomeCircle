# Fresh-install usability findings

Observed on 2026-10-04 in a disposable Home Assistant 2026.9.4 instance with HomeCircle beta 12. The installation completed and the card rendered fictional member and pet data. The detailed, private test log stays outside the public repository.

## Priority 1: finish setup without guidance

1. **Dashboard and card creation:** After the integration saves, create a HomeCircle dashboard and card only when no existing dashboard or card already serves that purpose. Beta 12 required the user to choose a dashboard type, find the card, save it, leave edit mode, and refresh the page. The development source now creates a storage-mode HomeCircle panel view with the full-screen Kiosk control after setup, preserves existing dashboards, and removes its own untouched dashboard on uninstall. It uses the active dashboard collection exposed by HA 2026.9.4's WebSocket registration and safely skips creation if that interface changes; check compatibility before supporting another HA version. **Verified in a fresh disposable browser setup with one sample member; existing Map dashboard remained.**
2. **HACS release choice:** The download dialog offered a branch commit instead of beta 12, and Home Assistant later advertised that commit as an update. All published HomeCircle releases are prereleases. HACS excludes prereleases from update checks by default, then falls back to the branch commit when no stable release exists. The beta 12 ZIP and `hide_default_branch` metadata are present. The setup guide now gives the exact beta 12 selection path and explains HACS's disabled-by-default pre-release switch for future beta updates. **Cause identified; release metadata should remain prerelease.**
3. **HACS versus Add integration:** The user expected the HACS download to complete setup. Explain that HACS installs files and Add integration creates the household. **Documentation improved.**

## Priority 2: make changes by task

1. **Options entry:** The initial Configure form mixes quick actions, household selections, places, and account controls. Start with a task choice and show only the relevant fields. The first implementation adds a task menu and a direct Battery and status sensors path. **Implemented in source; live acceptance pending.**
2. **Sensor lists:** Battery level previously showed every `sensor`, including backup sensors. Filter candidates by battery device class or an unclassified `%` unit while retaining existing saved mappings. **Implemented in source; live acceptance pending.**
3. **Map settings control:** The old Settings label led to the HomeCircle integration page and a separate Configure button. The card now uses a cog that opens the task-first HomeCircle options flow over the dashboard. The Person and tracker settings dialog puts the picker first and reveals available settings, including Remove a tracker where applicable, beneath it as soon as a selection is made. The removal picker is scoped to the selected person or tracker, and native Configure uses the same options step and choices. **Verified in the disposable instance through the scoped removal picker; saving a removal was covered by tests only.**
4. **Back navigation:** The review screen now offers Back to last member, Edit a member, and Save household choices. Returning to review keeps the full draft, including selections for other members. Tracker removal also has a review screen with Back and Save; Back restores the selected person and tracker. **Tracker-removal Back and review verified in the fresh disposable UI without saving a removal; whole-household Back acceptance remains pending.**

## Priority 3: clarify choices and evidence

1. **Tracker roles:** People and pet picker lists contain the same available device trackers because Home Assistant does not identify a tracker as a person or pet. The form now states that the user assigns each tracker to one role; its field labels and review identify the chosen role. Existing validation rejects duplicate roles and trackers linked to or active for a selected HA Person, using explicit associations rather than names. **Implemented in source; live acceptance pending.**
2. **Places:** The flow can create a real Home Assistant zone from a name, map location, and radius, then return to the household or member form with its selections intact. Primary homes count as Home for everyone, member homes count as Home for that member, and places such as work or school label Away locations. The former Ordinary places field is now Places shown while Away. **Implemented in source; live acceptance pending.**
3. **Location age:** The card now names the exact tracker or HA Person that supplied the map position alongside its evidence. A genuine location report age remains separate from HA's state-update age; an HA update never becomes a reported GPS fix. **Implemented in source; live acceptance pending.**

## User follow-up

The user reported that the remaining fresh-install checks appeared to pass and asked for street tiles to be on by default. The card default, new-card template, and automatic dashboard template now select OpenStreetMap tiles; an explicit Private choice remains available. The external tile request is disclosed in the editor and setup guide. This report is user acceptance of the observed workflows, not a claim that every branch was exercised or that production was changed.

The user identified tracker-only onboarding as the remaining confusing concept and chose to require a Home Assistant Person for every newly added person or pet. The development flow now offers Person creation, then shows tracker assignment, then member settings. The Add a tracker task follows that same screen order. It stages the HA Person link until final save. An older tracker-only member can be moved to a Person without losing its saved member settings. Automated tests cover the new path and legacy conversion. In the disposable dashboard, the revised Person screen, tracker screen, and Back navigation were verified. A fictional pet Person was created, assigned an existing pet tracker, configured, and saved; both its HomeCircle member and HA Person tracker link persisted through a separate-process restart. The card's default title now derives its Beta number from the integration manifest, so the next release will show its actual Beta number without a separate title edit.

HACS and Home Assistant's generic restart and integration-registration screens are external to HomeCircle. The flow should explain those transitions where it can.

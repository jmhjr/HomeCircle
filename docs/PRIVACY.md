# Privacy and security

## Never commit

Real personal coordinates, home/dorm/work addresses, API keys (including Google and Azure browser keys), Life360 credentials/tokens/cookies, HA tokens, family photographs, precise travel/history records, private instance URLs, and unnecessary personal entity IDs. This applies to source, fixtures, screenshots, logs, copied YAML, bundles, ZIP files, Git history, issues and release assets.

Public examples use `person.example_member`, `device_tracker.example_phone`, `zone.example_residence`, and explicit fictional display names. Avoid real coordinates altogether in examples; use null when no position is necessary. New synthetic coordinate fixtures must be clearly documented and reviewed before allowing them in the privacy checker. Generic avatar initials/icons replace photos.

## Reference custody

The raw frozen snapshot lives outside the repository under the task's restricted `work/homecircle-reference-v1/` directory. Files are mode 600 and directories mode 700. This is access restriction, not encryption. It contains private dashboard configuration and must never be published or copied wholesale into Git. Its private manifest records original paths and SHA-256 digests; the public capture summary contains only generic artifact counts and evidence limitations.

Do not use whole Home Assistant backups, `.storage`, databases, or credential-only files as public development inputs. The snapshot deliberately excludes credential-only key files and does not pretend to be a full HA recovery backup. Existing source directories remain untouched.

## Runtime requirements

Use HA authentication and authorization. Do not expose unauthenticated household data. Existing HA tracker integrations keep their own provider credentials. Each enabled built in tracker connection owns its credentials in Home Assistant's config entry storage; the current Life360 path stores a password or access token and a hashed account identity there. Credentials and the identity fingerprint are not sent to the card, diagnostic snapshot, or repository. HA config storage is not encrypted by HomeCircle. No HomeCircle telemetry or automatic support uploads, no background exports, no separate precise-location history store. HomeCircle provides no hosted account relay or diagnostic-upload service; enabled providers and explicitly enabled external features still make the requests disclosed below. Directly created tracker entities may be retained by Home Assistant Recorder under the user's Recorder settings. Redact diagnostics by allowlisting safe fields; never log raw entity attributes, coordinates, address strings, tokens or requests containing them.

Home Assistant's HomeCircle diagnostics export includes only provider status codes, aggregate tracker counts, and API operation times. It excludes the saved account configuration, member IDs, locations, raw responses, and exception text. Review any other Home Assistant diagnostics separately before sharing them.

The card shows a fixed, allowlisted connection message to Home Assistant admins when a built in provider needs attention. Non-admin viewers receive no account status in the authenticated snapshot. This status contains no identifiers, locations, credentials, raw errors, or API response fields.

Show last-reported age honestly and distinguish unknown freshness. Location displays are informational, not a guarantee of safety or real-time presence. Give users control over which household members and fields are shown on shared displays. Kiosk presentation is not an access-control boundary.

OpenStreetMap street tiles are enabled by default for new cards and reveal viewed areas and client network metadata; the setup guide and editor disclose this, and users can select a Private background. Selecting Satellite loads imagery directly from `basemap.nationalmap.gov` (USGS); that service receives viewed tile areas, client network metadata and site origin, without member names or HA credentials. The browser stores only the chosen view locally; Private overrides remembered external views. [USGS imagery service information](https://basemap.nationalmap.gov/arcgis/rest/services/USGSImageryOnly/MapServer) describes historical imagery and coverage. Optional IEM radar and HRRR forecasts are implemented with separate opt-in, as described below. Optional city lookup transmits exact tracker coordinates only after administrator opt-in, as described below. Future routing requires separate opt-in and disclosure. Restrict any future browser keys by origin and API, apply quotas, and never send server-only secrets to a browser. Optional provider failures must not erase basic HA presence.

When an HA person or selected tracker supplies a Life360 user or pet image, the card loads that portrait directly from `www.life360.com` or `life360-images-pub.life360.com`; Life360 receives the display's image request and network metadata. The card sends no HA page referrer. Other external image hosts are rejected, and initials remain visible if an image fails to load. HA-served portraits stay on the HA origin.

## Review and safeguards

`.gitignore` excludes private snapshots, secrets, credentials, images, archives and build products. The local pre-commit hook checks staged contents for common key/coordinate/address/entity patterns and unexpected binary files. Run `python3 scripts/check_public_files.py --all` before sharing. It is a conservative guard, not proof that a file is safe: inspect the diff and all generated release files manually. Do not bypass it to publish household data.

Before a release, review the complete Git history and release archive in addition to working files. Rotate/revoke exposed credentials at the issuing service if exposure occurs, remove sensitive history and artifacts, and follow the host's cleanup process; deleting a current file alone is insufficient.

Selecting a stale person card may make a bounded cloud read or request a phone update as described in the product guide. All selected household inputs must be readable by the viewer; Home Assistant phone commands additionally require control permission for the exact tracker and its registered notification target, plus the existing per-member opt-in. No inferred phone association is used. The snapshot exposes only the last selection-check time, fixed outcome and card-selection trigger; no provider error payload or credential is returned. Private field capture may retain these fields to distinguish prompted checks from ordinary reports.

External Life360 selection requests use only the installed integration’s registered `life360.update_location` action and an explicit selected tracker target, with control permission and persisted request limits. This may ask the provider to request a phone update; successful dispatch is not proof of delivery or a new fix.

Recent activity is stored locally in Home Assistant, bounded to seven days and 100 events per configured member. It retains only member/source identifiers, fixed status/outcome codes, observation times and genuine report times when supplied. It does not retain coordinates, routes, place names, portraits, raw entity attributes or credentials. Current household read authorization protects the entire activity projection; source labels are resolved only for configured inputs. Saved-configuration changes reset the log, and removing the integration deletes its store. Startup/reload boundaries are recorded rather than reconstructing events during gaps. HA storage/backups are not encrypted by HomeCircle; household users should treat activity times as private. If loading storage fails, the timeline remains in memory and explains that persistence is unavailable.

Person-card addresses use only the address attribute already reported by the exact selected usable map tracker, under the existing household read authorization. Defined place names take priority, and stale/unverified report times are qualified. With City lookup off (the default), HomeCircle makes no new external address lookup or coordinate transmission. Addresses are projected for current display only; the Recent activity log and private field capture retain no address field. Existing source integrations and HA Recorder retain source attributes under their own settings. Never include actual addresses in public fixtures, logs, screenshots or release notes.

The optional Radar map toggle is off on initial load and does not persist its enabled state. Enabling it loads public NEXRAD tiles directly from `mesonet.agron.iastate.edu`; IEM receives the viewed map tile areas and client network metadata, without household names, tracker identifiers, HA credentials or page referrer. Private map mode hides the toggle and prevents radar loading. Radar refreshes every five minutes while enabled and visible, and immediately when a hidden page becomes visible again. Playback may refresh expired metadata before starting; viewport changes request the tiles for the new area. Turning radar off or disconnecting the card removes the layer and timer.

Radar animation additionally fetches public IEM mosaic and HRRR model metadata, without credentials or referrer. Opt-in playback requests up to seven observed or nine forecast tile layers for the viewed area. These layers are removed when playback stops; no family names, tracker identities or HA tokens are sent. Private map mode prevents both metadata and tile requests.

Family-refresh results reflect reports observed within its two-minute window and remain fixed afterward. Completed or failed feedback clears after five minutes; request limits remain intact. Recent activity retains at most 25 freshness entries, evicting freshness before other events at the 100-event cap. All entries still expire after seven days.

## Explicit assigned-tracker family refresh

The family button is an optional, user-initiated exception to the ordinary HA-state boundary. For a compatible external Life360 integration, HomeCircle reads that integration's existing saved authorization in server memory and sends one authenticated HTTPS request to Life360's API for the selected Circle. It does not ask for a second account login, copy that authorization into HomeCircle storage, or send it to the browser, diagnostics or logs. This operation is unofficial and can stop working if the upstream layout/API changes.

The Circle operation is used only when the complete Circle membership is explicitly selected and a single enabled account can be resolved. Other explicitly assigned sources use supported entity-targeted Life360 actions, registered Home Assistant phone notification targets, or grouped HomeCircle-managed cloud report checks. Phone requests additionally require the member opt-in. Unsupported sources are skipped. No request is inferred from entity names or unselected Person associations. The caller must be able to read the configured household and control every planned tracker and notification target. Family dispatch is manual; source and Circle budgets are persisted, with a separate mixed-source button budget. Cloud checks do not promise a phone request. HA receipts are distinguished from genuine GPS report times, and dispatch does not prove a new fix or causality.

Family refresh is off by default, including for existing households after upgrade. Only an administrator can enable **Allow family location refresh** in Options. After opt-in, any viewer with the required household read and target control permissions may use the button; the standard Home Assistant user group normally grants control.

The current-arrival checkpoint is separate from the bounded Recent activity event list. It stores only the configured member and zone identifiers, an observed arrival timestamp when known, and an observation-gap flag in the existing local HA activity store. It retains the current occupancy beyond the seven-day event window, replaces it on observed departure/place change, resets with saved configuration changes, and is deleted when the integration is removed. It stores no coordinates, addresses or routes. Only the arrival time and fixed evidence flags are projected under household read authorization. Genuine Life360 arrival attributes come only from the exact explicitly selected usable map tracker with verified integration ownership; pet report timestamps are excluded. During a restart or unavailable gap, matching place evidence preserves the checkpoint while continuity is marked unconfirmed. A changed place during a gap does not fabricate an arrival time.

## Optional city lookup and local tracker photos

Only an administrator can enable City lookup. An authorized household snapshot starts a bounded HA-server request to Photon at photon.komoot.io for explicitly selected usable GPS positions outside named zones when a reported city is missing. Photon receives exact coordinates and server network metadata, but no names, entity identifiers, report timestamps, HA tokens or provider credentials. No key or account is required. Private map background blocks tiles; it does not override this separately enabled server-side option. Disable City lookup to stop coordinate transmission and lookup-result projection.

The local store retains at most 256 street/city results for seven days, keyed by a SHA-256 hash of rounded coordinate cells, plus up to 200 request times for the rolling daily limit. Coordinate hashes are not anonymization: cells can be guessed and cached addresses are private. HA storage and backups are not encrypted by HomeCircle. Requests are limited to 20/hour and 200/day, persisted before transmission, with five minutes between attempts per member. Errors retain ordinary address fallback and do not log replies/coordinates. Entry unload cancels work; removing the integration deletes its lookup store. Disabling leaves the cache locally until expiration/pruning or removal.

Tracker-only photo selection and crop stay in the browser until Save. Only the resulting 512-pixel JPG is uploaded to HA's authenticated native image service. HomeCircle stores an image ID; no photo goes to Photon or tracker providers. Native HA image URLs are readable without authentication by anyone holding the opaque link, so do not share those links publicly. Browser JPEG re-encoding discards original photo metadata. Clearing a reference, cancelling after upload, or removing HomeCircle does not delete HA's uploaded image. Manage retained assets and HA backups accordingly.

Life360 saved-place import is a separate administrator-initiated read through an existing saved connection. Authorization stays on the server. Circle names and saved-place coordinates/names/radii are retained in flow memory for review, then only explicitly confirmed places become editable HA zones. The importer neither synchronizes nor deletes existing zones; created zones remain after HomeCircle removal or a partial creation failure. No saved-place geocoding is performed.

## Optional provider scope and pending controls

Apple Find My and Life360 connections are optional and unofficial. Use accounts
and data you are lawfully entitled to access; local consent is not represented
as a provider permission grant. HomeCircle claims no Apple/Life360 affiliation,
endorsement, approval or logo right. Reports can be stale or unavailable and are
not an emergency or safety guarantee. The source-only package and remaining
terms/distribution decisions are recorded in the
[no-contact decision record](RELEASE-1.0-NO-OUTREACH-DECISION.md).

The current source candidate implements administrator **Manage direct
connections** in Options, with **Saved connection** and **Action → Pause/Resume**.
Apple denial stops the denied account while healthy siblings can continue;
Life360 denial stops that provider. Saved accounts, identities, selections and
local history remain. Normally persisted pause state survives restart; a storage
failure blocks current-process requests and shows a fixed error instead of
success, with no persistence promise after process loss if all disk writes fail.
Resume deliberately permits the selected provider again, including denied
accounts. It does not acknowledge recovery or reset its safeguard. The controls
cover HomeCircle polling and its manual/auxiliary requests, not another
integration's polling, map/city choices or Recorder retention. No hosted remote
kill switch is provided. Affected native validation and final qualification
remain pending in the [active tracker](RELEASE-1.0-FIRST-RELEASE-TRACKER.md);
source inspection does not establish a published-beta or native pass.

## Apple Find My connection

Beta 19's experimental Find My connection signs in to Apple from HA and prepares a local identity runtime before asking for account credentials. It downloads required public Apple software when needed and maintains this connection's own client identity. Fresh discovery temporarily recovers broader Keychain material to find item keys, then saves only explicitly selected items. It does not join a new Keychain trust peer. See the [setup guide](FINDMY-SETUP.md), [runtime provenance](../custom_components/homecircle/_findmy_runtime/PROVENANCE.md) and [tested scope](FINDMY-BETA19-PACKAGING-VALIDATION.md).

Find My's minimized encrypted vault contains the account identifier/email, selected accessory keys, client identity and local provisioning state, and the report-service token. Other service grants and account details are removed. The decryption key is stored alongside the vault in HA storage. Anyone with sufficient access to that storage or its backups can recover the connection, so protect both. Apple passwords, verification codes and trusted-device unlock passcodes stay transient and are not saved in config entries or the vault. No credentials or recovered keys are sent to household browsers or sanitized diagnostics.

Authorized household viewers can read the configured item locations. HomeCircle retains each selected item's last usable report, including its source time and estimated accuracy; an empty successful poll does not erase that older location or make its timestamp newer. HA Recorder and backups may retain tracker states and locations under the user's settings. Disconnecting deletes this connection's active HomeCircle session and keys, without deleting existing history or backups.

The unreleased stable candidate also keeps an encrypted, account-bound identity ledger with keyed commitments of accessory key material and saved display settings. This supports reselecting an omitted item without keeping its tracking keys. Matching requires all three accessory secrets; names and old registry/history entries are not proof. The ledger and its random secret are deleted with the account vault on Disconnect, so a later re-add cannot always recover an old identity if the required proof is no longer available. Existing backups can retain both selected keys and prior ledgers.

A separate owner-only recovery safeguard stores a hash of the authenticated account identifier and local counts of refused, uncertain and verified exchanges. This hash is pseudonymous, not anonymization. The safeguard contains no password, passcode, service token, accessory key or location. It survives setup cancellation, reconnect, HA restart, Disconnect and integration removal so these operations cannot silently replenish its local threshold. An explicit administrator acknowledgement clears local unresolved counts; verified counts remain. This does not reset or describe Apple's retry allowance. Unsafe or unreadable guard storage prevents another recovery proof, while an existing report-only connection can continue polling. The candidate additionally binds each account’s ledger entry and changing generation to a private continuity witness under `.cache/homecircle_findmy/recovery_guard`. Ordinary Home Assistant backups exclude `.cache`, and a configuration restore removes the live witness. A missing witness, an older ledger paired with a newer witness, or an older ledger format blocks new device-passcode recovery until that authenticated account is explicitly reviewed. Status checks and ordinary saved-item polling never recreate trust. First use, upgrade from the older safeguard, or cache cleanup can also require this review. Acknowledging one account does not acknowledge others. This blocks silent replenishment after an ordinary backup restore; it does not reconstruct lost observations. Protect the full live installation. A complete filesystem or VM snapshot can roll back both ledger and witness, and an older backup can also replace the fixed code with an older package. Those cases require reinstalling the fixed candidate and reviewing recovery before use; this local witness is not an external monotonic counter. Backups and local acknowledgement never reset Apple’s server-side allowance.

Verified recovery material and an opened peer can remain in memory for the lifetime of a setup to finish a failed key download without another passcode proof. Reuse requires the same authenticated account and exact recovery record. Closing/expiring setup drops those references and broad key collections; this is not a guarantee of memory zeroization. The unreleased hardening candidate bounds recovery key-derivation work, runs it off the main loop, and drains it before returning cancellation. The affected Find My background failures are collected without asyncio automatically logging their raw exception details. Failed worker cleanup still retains the handle needed to retry reaping it while dropping the closed provider's transient cache and identity references.

Find My diagnostics use allowlisted fixed statuses and aggregate counts. Raw account or item identifiers, keys, tokens, coordinates, response bodies and exception text are excluded. Review any other HA logs or screenshots before sharing them; do not share vault files or setup credentials.

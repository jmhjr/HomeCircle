# Vendored FindMy SDK

MIT-licensed FindMy.py, pinned to parawanderer/FindMy.py commit 7969003ca785658369b650f75d9e7ca519566bf6.

Upstream: https://github.com/parawanderer/FindMy.py/tree/7969003ca785658369b650f75d9e7ca519566bf6

The upstream MIT copyright and license are preserved in LICENSE.md. Python import paths are rebased to this private package namespace to avoid replacing another integration's installed FindMy package. Runtime dependencies are provided through HomeCircle's declared requirements. Only source, protocol definitions and public escrow root certificates are included; no account data, exports, library cache, tests or binaries are vendored. This candidate is not yet a published beta provider.

Local HA runtime adaptation: identity-library initialization runs in an executor; the public library cache is written only when missing, under a process thread lock, using a temporary file and atomic rename to avoid blocking HA’s event loop. No protocol or cryptographic behavior is changed.

Local rejection diagnostics: InvalidCredentialsError optionally carries only a bounded integer Apple status code and an allowlisted init/complete phase. The two Grand Slam rejection sites populate them so HomeCircle can log those fields without exposing Apple response text. This diagnostics adaptation does not alter requests or cryptographic behavior.

Local candidate GSA transport label: AsyncAppleAccount has an optional `gsa_client_info` override. HomeCircle onboarding sets the Android Apple Music client label reported in SideStore/SideSign PR #5 because its local anisette implementation uses Android ADI libraries. The configured label applies to GSA authentication, verification and the follow-up MobileMe delegate exchange. Persistent device/local-user/ADI IDs, serials, provisioning secrets and SRP computation stay unchanged; the native platform label is centralized by findmy_profile.py. Restored onboarding uses the same fixed GSA label. A Linux synthetic-account comparison changed the init rejection from -80045 to -20101. This is not full authentication acceptance; owner login, two-factor and downstream item discovery remain unverified. Reference: https://github.com/SideStore/SideSign/pull/5 .

Local pushed-code handling: after a successful complete exchange with a verified SRP server proof and decrypted SPD, `Status.hsc=409` without an auth-mode field enters REQUIRE_2FA instead of proceeding to delegates. The already-sent trusted-device code is the only method offered for that transient state; no SMS discovery or duplicate code request is made. Verification retains the configured GSA client label. Rejected exchanges and invalid server proofs still fail, and normal legacy auth states remain distinct. No new status implies completed authentication or Keychain trust.

Local verification diagnostics: transient allowlisted stage, validation HTTP status and follow-up login-state markers distinguish code validation from reauthentication and MobileMe delegates. HomeCircle logs only those markers and bounded numeric rejection/SRP metadata, never the code, credentials, token, response text or exception text. These markers are not added to the saved account mapping.

Delegate candidate and diagnostics: require a nonempty PET before requesting services, use the configured Android client-info label for the delegate exchange, and expose only PET-presence, HTTP/numeric statuses and localized-error/unauthorized booleans to the own-code diagnostic filter. No token value or response text is logged or persisted. The owner reached AUTHENTICATED after verification but the earlier Mac-labelled delegate failed; this candidate still requires a live delegate/item-discovery check.

Native profile audit: HomeCircle applies one Android platform to fresh onboarding and both report-session restore paths. Provider-built labels also cover report polling, announcements and terms request builders. CloudKit uses that platform for request headers and operation metadata while retaining its service bundle; escrow retains the secure-backup bundle. The anisette dependency receives the same description before provisioning, including when device.json is restored into its isolated VM. Generic upstream defaults/examples are not emitted by these native paths. No existing vault is rewritten by this adaptation.

Apple G3 trust: Android provisioning lookup selects gsd.apple.com. Its chain requires Apple Root CA G3, obtained from Apple's official PKI URL and pinned to SHA-256 63343abfb89a6a03ebb57e9b3f5fa7be7c4f5c756f3017b3a8c488c3653e9179. The SDK trust context adds it alongside system trust and the existing fingerprint-checked Apple root. Native ADI provisioning uses that same context. Hostname checking and CERT_REQUIRED remain enabled. No certificate verification bypass or system trust-store mutation is performed.

# Independent ordinary restore evidence review

This consumer checks the R5 QA head `4957b3f44e84837e01af731286c0728a4127aea3` and exact
native run `39721983991`. The consumer revision is immutable after this binding.
Actual artifact qualification still requires the completed successful run.
It performs no Git, network, VM, Home Assistant, provider or account operation.
It never imports or executes fixture code. Only literal data is read from
already hash-verified packet Python through bounded AST traversal.

The independent input map binds all 26 fixture files and the exact workflow.
The workflow's own all-file map must match those same bytes. The original
113-member product ZIP is checked against its exact known digest and inventory;
111 members are independently matched to the frozen canonical Git source
inventory, and both generated frontend members match the prior qualified bytes.
The product manifest remains unchanged. No QA dependency is inserted.

Root must supply separately downloaded and GitHub-verified metadata identifying
the exact successful push run, attempt, QA head, workflow digest, artifact name,
artifact identity and downloaded ZIP digest. This file is outside the artifact.
It is a trust input, not a claim inferred from a receipt. The collector requires
exactly five JSON members: host plus the four declared startup phases.

Every receipt has explicit nested keys and exact scalar types. Counts, network
windows, image identities, dependency origins, ordinary resolver observations,
storage contexts, Recorder continuity, provider-denial hooks and cleanup are
checked. The guard sequence must be **2, 3, 2, 2**, with review and proof admission
blocked on the first automatic restored process and the subsequent restart.
Manual guard exports/imports and post-restore owner acknowledgments must be zero.
Raw source report coordinates, credentials, ledgers and archive contents are
not public evidence and are never requested by this consumer.

The eight finite contracts use fictional schema examples and frozen public
inputs. They reject the earlier coordinated manifest/payload hash false
positives, loose numeric types, extra nested fields, duplicate JSON/ZIP members,
manual repair, missing guard blocking, unobserved ordinary installation and
misbound root metadata. Those contracts are consumer checks, not a native run.

Outputs are new files only, outside the frozen fixture. Existing input/output
files are never overwritten; failures expose only fixed labels. A successful
replay qualifies the declared synthetic partial restore with environmental
transport instrumentation. It does not qualify real provider authentication,
full encrypted cloud backup, a full VM snapshot rolling back both guard files,
pre-fix code restored by an older archive, or a stable release.

R5 retains the strict runtime configuration equality gate and requires the host
`guest_failures` field to be exactly an empty list. After the verified consumed
grant, the fixture checks the restored raw baseline and actual rollback guard
before the existing runtime observation. This loads its lazy guard target before
the unchanged strict six-target boundary check. Atomic publication, post-grant
input binding and all success gates remain intact. All 113 product members are
unchanged. Earlier failed runs and their original consumers are preserved.
